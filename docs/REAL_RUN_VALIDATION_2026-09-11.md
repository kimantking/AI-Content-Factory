## 발견 원인과 수정

1. 스튜디오의 음수 가로 여백과 grid 카드의 최소 폭 때문에 PC·모바일에서 가로 넘침이 생겼다. 음수 가로 여백을 제거하고 카드에 `min-w-0`을 적용했다.
2. Ollama가 꺼져 실제 대화가 실패했다. 기존 서버를 시작해 같은 대화부터 재검증했다.
3. 음성 공급자가 mock이고 기존 Voice ID가 계정 목록에 없었다. 기존 키를 유지하면서 사용자가 선택한 실제 한국어 음성으로 수정했다.
4. Ollama의 빈 JSON이 유효한 출력으로 처리돼 전략의 `angle` 접근에서 실패했다. 빈 객체/배열/null을 재생성 대상으로 처리하고 반복 실패는 오류로 반환한다.
5. 텍스트 작업 재시도가 처음부터 실행됐다. Celery 재시도에서 checkpoint resume을 사용한다.
6. 단계 상태가 긴 provider 호출과 같은 transaction에 있어 실패 시 이전 단계로 되돌아갔다. 호출 전 현재 단계를 commit한다.
7. Docker에 한국어 폰트가 없어 사각형 자막이 생성됐다. `fonts-nanum`을 추가했다. 이미 생성된 실제 이미지·음성을 보존하고 렌더링 checkpoint부터 재실행했다.
8. 최종 영상 플레이어가 PC에서 지나치게 높았다. 높이를 viewport의 70% 이내로 제한하고 MP4 다운로드 링크를 추가했다.
9. 중지 작업에 UI 재시작 기능이 없었다. 재시작 버튼과 텍스트/미디어 checkpoint별 분기를 추가했다.
10. 실제 중지 시 worker의 늦은 RUNNING 갱신이 취소를 덮어썼다. revoke 후 CANCELLED를 다시 확정하고 중지 상태의 단계 실행 및 실패 덮어쓰기를 막았다. 동일 실제 작업에서 다시 검증했다.

## 검증 범위 및 남은 제한

- 이번 최종 MP4는 IMAGE_MOTION 방식이다. Google Veo는 모델 조회와 mock adapter 경로만 확인했으며 실제 유료 Veo 영상 합성은 수행하지 않았다.
- 소리는 실제 합성 결과와 MP4 오디오 트랙, 음소거 해제 재생 및 음량/디코딩으로 검증했다. 현재 도구는 오디오 입력 청취를 지원하지 않아 직접 귀로 들은 품질 평가라고 주장하지 않는다.
- 생성된 음성을 Google로 전송하는 추가 전사 검사는 자동 승인 검토가 별도 전송 승인이 필요하다는 이유로 차단했다. 전송은 실행되지 않았으며 사용자에게 승인 질문을 남겼다.
- UI의 $0.0000은 공급자 단가를 알 수 없는 기록을 포함하므로 실제 무료 제작을 의미하지 않는다. Google/ElevenLabs 실제 생성 사용량의 청구액은 이 점검에서 확정하지 않았다.

## 실제 움직이는 영상 후속 작업

- Veo 3.1 Standard의 8초 생성 예상 비용 $3.20를 호출 전 예산 검사와 생성 후 비용 기록에 반영했다. 이는 청구 확정값이 아닌 ESTIMATED 값이다. 다른 모델의 비용은 여전히 UNKNOWN이다.
- Veo 3.1에서 1080p 세로 출력 해상도를 명시하고 생성 클립 길이를 실제 요청값인 8초로 기록한다. 최종 편집은 내레이션 길이에 맞춰 자른다.
- Veo 제출·진행 조회·연결 검사에서 API 키를 URL 대신 인증 헤더로 보낸다.
- 격리 DB에서 Google adapter mock 검사 21개 통과. 유료 영상 생성 검증과 구분한다.
- 기존 미디어 한도 $1.50를 넘는 실제 제작은 사용자에게 $10(3장면) 또는 $3.50(1장면) 한도를 질문한 상태다. 실제 Veo 생성과 결과 재생은 아직 수행하지 않았다. 기존 IMAGE_MOTION 결과는 보존되어 있다.

## 영상 방식·생성 범위 선택 UI 후속 검증

- 홈(`/app`), 만들기(`/create`), 통합 제작(`/compose`)에 공통 선택 카드를 적용했다. 이미지 모션과 Veo를 구분하고, Veo는 1장면 또는 최대 3장면을 선택한다. 나머지 장면은 이미지 모션으로 처리한다.
- 선택값은 `campaigns.video_plan`에 저장한다. 마이그레이션 `0016_video_plan` 적용. 기존 행은 nullable이며 기존 영상 파일을 보존한다.
- 선택한 Veo 한도는 추가 제한이다. 기존 미디어·캠페인·일일·월간 예산을 올리지 않는다. 자동 승인 검토에서 예산 상향 변경이 거부되어 해당 변경은 적용하지 않았다.
- Google 모델과 기존 예산을 읽기 전용 API로 조회해 예상액과 초과 안내를 표시한다. 현재 미디어 $1.50 / 캠페인 $2.00이므로 유료 Veo 시작은 차단된다.
- Docker backend/worker/frontend 빌드·실행 및 프런트엔드 타입 검사 통과. 별도 검증 DB에서 mock 회귀 검사 31개 통과(선택 저장·잘못된 선택 거부·장면 수 제한·재시도 재사용·기존 예산 유지·Google adapter).
- 실제 브라우저에서 1장면→3장면 선택 시 예상액 $3.20→$9.60 갱신 확인. PC 1440px / 모바일 390px에서 선택 영역 가로 넘침 없음.
- 실제 UI에서 예산 초과 상태로 제작 시작 시 서버 오류 안내 확인. 해당 검증 주제의 캠페인 생성 건수 0, 기존 완료 캠페인 SUCCESS 및 기존 MP4 파일 존재를 확인했다.
- 이 후속 작업에서 실제 Veo 유료 생성 또는 SNS 게시를 실행하지 않았다. 실제 움직이는 Veo 결과의 생성·재생 검증은 여전히 미완료다.

## 사용자 $10 승인 후 실제 Veo 제작·재생 검증

- 사용자가 이번 작업에만 최대 $10을 명시적으로 승인했다. 기존 완성본을 별도 캠페인 `8d7aebff-5800-4db3-9727-e937f57e5124`로 복제하고 이미지·Hana Lee 음성을 재사용했다. 전용 실행 프로세스의 미디어·작업 한도만 $10으로 설정했으며 `.env`와 전역 예산은 변경하지 않았다.
- 실제 Google Veo 3.1 Standard로 1080×1920, 8초 장면 3개를 생성했다. 김과 빗방울, 인물의 움직임, 차를 들어 마시는 동작을 확인했다. 예상 영상 비용 합계 $9.60이며 청구 확정 금액은 아니다.
- 첫 장면 생성 후 DB의 60초 idle-in-transaction 제한으로 결과 기록에 실패했다. 유료 생성·poll 전에 DB 트랜잭션을 commit하도록 수정했다. 저장된 operation을 재사용하여 첫 장면을 재생성하지 않고 복구했다. 나머지 장면 저장은 정상 통과했다.
- 같은 문제를 예방하도록 FFmpeg 렌더 전에도 트랜잭션을 해제했다. 격리 DB의 실제 1초 유휴 제한과 느린 mock 공급자 회귀 검사 7개 통과.
- 최종 MP4: `outputs/8d7aebff-5800-4db3-9727-e937f57e5124/youtube_shorts/final.mp4`, 1080×1920, 30fps, 약 16.57초, 10,138,302 bytes.
- 실제 브라우저 플레이어에서 paused=false 재생을 확인한 뒤 ended=true, currentTime=duration=16.566667, muted=false 확인. 시간별 추출 프레임에서 동작과 한국어 자막 확인(`outputs/veo-final-contact.png`).
- UI 다운로드 실행 및 HTTP 200, attachment final.mp4 확인. 다운로드 응답과 디스크 MP4의 SHA-256 일치.
- 음성 트랙 전체 FFmpeg 디코딩 exit 0. mean -18.5 dB / peak -6.4 dB. 직접 귀로 들은 주관적 음질 평가와 구분한다. Google 추가 전사 검사는 수행하지 않았다.
- 기존 IMAGE_MOTION 결과와 새 Veo 결과를 모두 보존했다. SNS 게시를 실행하지 않았다.

## 후속 코드 정리 및 회귀 검증

- 실패·취소 단계가 RUNNING으로 표시되는 문제와 이미지 생성 성공이 아직 생성되지 않은 AI_VIDEO 장면의 성공으로 표시되는 문제를 수정했다.
- 미디어 화면의 비용은 기록된 금액이며 예상 단가를 포함한다고 표시하고, 기본 예산과 구분했다. 기본 예산을 상향하지 않았다.
- 참조 이미지가 없으면 유료 요청 전에 실패하며, 명시적 Veo 한도를 선택했는데 실제 공급자 단가를 모르면 생성하지 않는다.
- 격리 DB에서 관련 회귀 검사 53개 통과, 컨테이너 localhost Ollama 조건에 의존하는 2개 skip. 저장소 설정의 Ruff 검사와 프런트엔드 프로덕션 빌드·타입 검사 통과.
- 장면 제한·재시도·중지 회귀 검사를 GitHub CI에 추가했다. 추가 유료 생성은 수행하지 않았다.
