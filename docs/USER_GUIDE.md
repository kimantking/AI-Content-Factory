# USER GUIDE

Practical walkthrough of the main workflows. For a gentler intro see
`BEGINNER_GUIDE.md`; for setup see `SETUP_WIZARD.md`.

## 1. Make content

`/create` → topic + optional reference URLs + execution mode + per-platform
3-state SNS selection + quality preset. The cost preview updates live; UNKNOWN
lines are shown as such, local work as "LOCAL PROCESSING · API ₩0". Submit →
the pipeline runs for the selected platforms only. The result links straight to
the content in the library.

## 2. Browse / reopen

`/library` — card or table view, search (topic + script), filters
(platform / content-type / status / governance / publish-state / date), sort
(newest / views / revenue / profit), pagination. Click a card → detail with 12
tabs. The **preview** tab plays the real MP4 when the file exists. **plateform
versions** lets you add a platform later (only that platform is generated).

## 3. Learn only

`/learn-studio` — paste reference URLs, choose purpose + scope, "학습만 하기".
No campaign, media, render or publish is created. Results: learned Hook / Story /
Editing / B-roll / Subtitle / Voice / Audio / Thumbnail patterns → datasets,
skills, prompt candidates, creative recipes. Review candidates in `/prompt-lab`
(they are never auto-promoted to production).

## 4. Review & publish

`/governance` — the review center. A block is shown in plain language with a
cause and a one-click safe fix where possible (music replace / B-roll replace /
disclosure add / attribution add). Legal calls are never auto-approved.
`/publishing` — connect accounts, final confirm before a production publish.
`/calendar` — month view of scheduled publishes by platform / status.

## 5. Manage

`/portfolio` (channels), `/analytics`, `/autopilot` (OFF / 추천만 / 자동 제작 /
게시 전 승인 / 완전 자동 — full-auto requires an explicit budget/limits/governance
confirm). Reposition suggestions are experiments, never an automatic channel
identity change.

## 6. Local AI & models

`/settings/local-ai` — Ollama status, the model registry (python / local / cloud
with health + pricing state), per-task measured model performance, and a
benchmark button. `/system` — plain-language health of every component.
